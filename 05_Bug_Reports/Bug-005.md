# BUG-005 - Incident Point Value Automatically Changes to 2147483647 When an Extremely Large Number is Entered

## Bug ID
BUG-005

---

## Module
Student

---

## Feature
Behaviour Record / Incidents

---

## Bug Title
Incident point value is automatically changed to **2147483647** when an extremely large number is entered.

---

## Environment

| Parameter | Value |
|-----------|-------|
| Application | School Management System |
| Module | Student Management |
| Feature | Behaviour Record / Incidents |
| Browser | Google Chrome |
| Operating System | Windows 11 |
| User Role | Admin |
| Build | Current Testing Build |

---

## Preconditions

- User is logged in as **Admin**.
- User has permission to create Behaviour Incidents.
- Behaviour Record module is accessible.

---

## Steps to Reproduce

1. Login as **Admin**.
2. Navigate to **Student → Behaviour Record → Incidents**.
3. Click **Add Incident**.
4. Enter a valid **Title**.
5. Enter a valid **Description**.
6. Enter **999999999999** in the **Point** field.
7. Click **Save**.
8. Observe the saved Point value.

---

## Test Data

| Field | Value |
|--------|-------|
| Title | Late Attendance |
| Description | Student arrived late to class |
| Point | 999999999999 |

---

## Expected Result

The system should validate the Point field and reject values exceeding the allowed range.

An appropriate validation message should be displayed, for example:

> **"Point value exceeds the maximum allowed limit."**

or

> **"Please enter a valid point value."**

The record should not be saved until a valid value is entered.

---

## Actual Result

The system accepts the extremely large value but automatically saves it as **2147483647** (maximum 32-bit integer value) instead of showing a validation error.

---

## Impact

- Incorrect incident point values are stored.
- Behaviour score calculation becomes inaccurate.
- Data integrity is compromised.
- Users receive no indication that their entered value was modified.
- Reports and disciplinary calculations may produce incorrect results.

## Root Cause (Possible)

- Integer overflow is not properly validated.
- Backend automatically truncates or converts values exceeding the database integer limit.
- Missing server-side maximum value validation.
- Frontend numeric validation is not implemented.

---

## QA Comments

The application should never silently modify user-entered values. Instead, it should validate the maximum acceptable point value before saving and inform the user when the entered value exceeds the supported range.

---

## Suggested Fix

- Implement both client-side and server-side numeric range validation.
- Define a business limit for incident points (e.g., 0–100 or 0–1000).
- Prevent integer overflow before database insertion.
- Display a meaningful validation message instead of automatically replacing the value with **2147483647**.
