# BUG-010 - Fees, Library, and HR Navigation Menus Are Non-Functional for Accountant Role

## Bug ID

BUG-010

---

## Module

Navigation Bar

---

## Feature

Role-Based Navigation (Accountant)

---

## Bug Title

Fees, Library, and HR menu items are visible but non-functional in the Accountant role.

---

## Environment

| Parameter | Value |
|-----------|-------|
| Application | School Management System |
| Module | Navigation Bar |
| Feature | Sidebar Navigation |
| Browser | Google Chrome |
| Operating System | Windows 11 |
| User Role | Accountant |
| Build | Current Testing Build |

---

## Preconditions

- User is logged in as **Accountant**.
- Accountant role has access to the application.
- Sidebar menu is displayed successfully.

---

## Steps to Reproduce

1. Login as **Accountant**.
2. Click **Fees** from the sidebar.
3. Click **Library** from the sidebar.
4. Click **HR** from the sidebar.
5. Observe the application behavior.

---

## Test Data

| User Role | Accountant |

---

## Expected Result

The system should behave according to the assigned permissions.

- If the Accountant has access:
  - Navigate to the respective module successfully.

**OR**

- If the Accountant does not have permission:
  - Hide the menu items completely **or**
  - Display an appropriate message such as:
    - *"Access Denied"*
    - *"You do not have permission to access this module."*

---

## Actual Result

The **Fees**, **Library**, and **HR** menu items are visible in the sidebar and appear clickable.

However:

- Clicking the menu does nothing.
- No page is opened.
- No content is loaded.
- No error message is displayed.
- No access denied message is shown.

The menu items appear to be broken or disconnected from their respective modules.

---

## Impact

- Creates confusion for Accountant users.
- Users cannot determine whether the feature is unavailable or broken.
- Poor user experience due to misleading navigation.
- Indicates incomplete role-based permission implementation.
- Increases support requests because visible features appear unusable.

## Root Cause (Possible)

- Sidebar menus are displayed without validating role permissions.
- Navigation routes are missing or not mapped for the Accountant role.
- Role-based authorization is implemented inconsistently.
- Click events are not bound to the menu items.

---

## QA Comments

Menu items should never appear clickable unless they are functional. If a role does not have access to a module, the menu should either be hidden or provide a clear access restriction message instead of remaining inactive without feedback.

---

## Suggested Fix

- Review the Accountant role permission matrix.
- Hide unauthorized menu items from the sidebar.
- Display a proper **Access Denied** message when unauthorized users attempt to access restricted modules.
- Verify that all visible navigation items have valid route mappings.
- Perform regression testing for all role-based navigation menus to ensure consistency.
