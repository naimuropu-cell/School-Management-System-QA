# BUG-020 - Student Promotion Creates Duplicate Active Student Records Across Academic Sessions

## Bug ID

BUG-020

---

## Module

Student

---

## Feature

Student Promotion

---

## Bug Title

Student Promotion creates duplicate active student records instead of updating the existing student profile.

---

## Environment

| Parameter | Value |
|-----------|-------|
| Application | School Management System |
| Module | Student |
| Feature | Student Promotion |
| Browser | Google Chrome |
| Operating System | Windows 11 |
| User Role | Admin |
| Build | Current Testing Build |

---

## Preconditions

- Admin is logged into the application.
- A student already exists in the current academic session.
- Promotion module is accessible.

---

## Steps to Reproduce

1. Login as **Admin**.
2. Navigate to **Student → Student Promotion**.
3. Select the current Academic Session.
4. Select a student for promotion.
5. Promote the student to the next class/session.
6. Open **Student List**.
7. Search using the student's Admission Number or Student ID.

---

## Test Data

| Field | Value |
|--------|-------|
| Student | Existing Student |
| Current Class | Class 9 |
| Promoted Class | Class 10 |

---

## Expected Result

The system should update the student's academic information and maintain a **single active student profile**.

- Student ID should remain unchanged.
- Admission Number should remain unchanged.
- Only the class/session should be updated.

---

## Actual Result

The promotion process creates a **new active student record** while the previous record also remains active.

As a result:

- Two active student profiles exist.
- Same Admission Number/Student ID appears multiple times.
- Both records are usable.

---

## Impact

- Duplicate student records are created.
- Attendance may be recorded against different records.
- Fees may be generated twice.
- Examination results become inconsistent.
- Reports contain duplicate students.
- Student history becomes unreliable.
- Data integrity is severely compromised across multiple modules.

## Regression Required

Yes

---

## Root Cause (Possible)

- Promotion inserts a new student instead of updating the existing record.
- Student ID mapping is lost during promotion.
- Academic session logic creates duplicate active records.
- Database constraints are missing.

---

## QA Comments

This is a **Critical** issue because it corrupts the master student data. Multiple active records for the same student affect Attendance, Examination, Fees, Results, Reports, and overall academic history. This bug has a high business impact and should be fixed before production deployment.

---

## Suggested Fix

- Update the existing student record during promotion instead of creating a new one.
- Maintain a single active student profile.
- Preserve Student ID and Admission Number across academic sessions.
- Add backend validation to prevent duplicate active student records.
- Perform end-to-end regression testing on Promotion, Attendance, Fees, Examination, and Reporting modules.
