# BUG-009 - Saving Homework Evaluation Redirects to 500 Internal Server Error Despite Data Being Saved Successfully

## Bug ID

BUG-009

---

## Module

Homework

---

## Feature

Homework Evaluation

---

## Bug Title

Saving Homework Evaluation redirects to **500 Internal Server Error** even though the evaluation data is saved successfully.

---

## Environment

| Parameter | Value |
|-----------|-------|
| Application | School Management System |
| Module | Homework |
| Feature | Homework Evaluation |
| Browser | Google Chrome |
| Operating System | Windows 11 |
| User Role | Teacher / Admin |
| Build | Current Testing Build |

---

## Preconditions

- Teacher/Admin user is logged in.
- Homework has already been assigned.
- Student has submitted the homework.
- Homework Evaluation page is accessible.

---

## Steps to Reproduce

1. Login as **Teacher** or **Admin**.
2. Navigate to **Homework → Homework Evaluation**.
3. Select a submitted homework.
4. Enter marks and evaluation comments.
5. Click **Save**.
6. Observe that the system redirects to a **500 Internal Server Error** page.
7. Login as **Student**.
8. Navigate to the submitted homework and verify the evaluation.

---

## Test Data

| Field | Value |
|--------|-------|
| Homework | Existing Homework |
| Marks | 80 |
| Remarks | Good Work |

---

## Expected Result

- Homework evaluation should be saved successfully.
- The system should display a success message.
- User should remain on the evaluation page or be redirected to the evaluation list.
- No server error should occur.

---

## Actual Result

- After clicking **Save**, the system redirects to a **500 Internal Server Error** page.
- Despite the error, the evaluation data is successfully saved.
- Students can view the saved marks and evaluation from their account.

---

## Impact

- Teachers believe the save operation has failed.
- Users may submit the evaluation multiple times, creating confusion or duplicate operations.
- Poor user experience due to misleading server error.
- Indicates improper response handling after successful database transaction.

## Root Cause (Possible)

- Database transaction completes successfully.
- Server throws an exception while returning the response.
- Redirect URL is invalid or unavailable.
- Controller/service returns an incorrect response after successful save.
- Unhandled backend exception occurs after data persistence.

---

## QA Comments

The evaluation is successfully stored in the database and is visible in the Student portal; however, the application incorrectly displays a **500 Internal Server Error** after saving. This is a backend response-handling issue rather than a data persistence issue and may lead users to believe that the evaluation was not saved.

---

## Suggested Fix

- Review the backend controller/action executed after the save operation.
- Ensure a proper success response or redirect is returned after the database transaction.
- Handle exceptions gracefully and prevent false **500 Internal Server Error** responses.
- Verify that the frontend receives the correct HTTP status (200/201) after a successful save.
- Perform regression testing to confirm that evaluation data is saved only once and no duplicate submissions occur.
