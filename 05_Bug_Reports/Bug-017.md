# BUG-017 - Student Profile Can Be Deleted Without Confirmation Dialog

## Bug ID

BUG-017

---

## Module

Student

---

## Feature

Student Management

---

## Bug Title

Student profile is deleted immediately without any confirmation dialog.

---

## Environment

| Parameter | Value |
|-----------|-------|
| Application | School Management System |
| Module | Student |
| Feature | Student Management |
| Browser | Google Chrome |
| Operating System | Windows 11 |
| User Role | Admin |
| Build | Current Testing Build |

---

## Preconditions

- User is logged in as **Admin**.
- At least one student record exists.
- User has delete permission.

---

## Steps to Reproduce

1. Login as **Admin**.
2. Navigate to **Student → Student List**.
3. Select any existing student.
4. Click the **Delete** icon/button.
5. Observe the system behavior.

---

## Test Data

| Field | Value |
|--------|-------|
| Student | Existing Student Record |

---

## Expected Result

The system should display a confirmation dialog before deleting the student.

Example:

> **"Are you sure you want to delete this student?"**

Options:

- Yes
- No

The student should only be deleted after user confirmation.

---

## Actual Result

The student record is deleted immediately after clicking the Delete button without displaying any confirmation dialog.

---

## Impact

- Student records can be deleted accidentally.
- Permanent data loss may occur.
- Users cannot cancel unintended delete operations.
- Poor user experience and data protection.

---

## Severity

Major

---

## Priority

High

---

## Bug Type

Functional / UX

---

## Status

Open

---

## Reproducibility

100%

---

## Regression Required

Yes

---


## Root Cause (Possible)

- Delete confirmation modal is not implemented.
- Delete API is called immediately on button click.
- Missing client-side confirmation.

---

## QA Comments

Deleting critical records without confirmation is a usability and data safety issue. Confirmation should be mandatory before performing irreversible operations.

---

## Suggested Fix

- Display a confirmation dialog before deletion.
- Require explicit user confirmation.
- Consider implementing Soft Delete instead of permanent deletion.
